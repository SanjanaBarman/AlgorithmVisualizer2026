Architectural Mechanism & Constraints

The Binary Search structural design operates under a strict **Divide and Conquer** protocol. Instead of validating elements indexing sequentially like Linear Search at a costly $O(N)$ scanning footprint, Binary Search iteratively eliminates precisely half of the remaining search window at each evaluation junction.

The Monotonicity Constraint Rule: The primary system prerequisite for running Binary Search is that the target linear matrix data structure **must be sorted monotonically** (ascending or descending). Without complete array sorting, the mathematical calculation of the comparative bounds collapses.

At each conditional matching cycle, the calculation maps down to a secure index pointer offset calculation:
Mid = Low + ⌊(High - Low) / 2⌋.

Mathematical Proof of Time Complexity

The operational time complexity bounds of Binary Search chart mathematically directly to a logarithmic function metric: **$O(\log_2 N)$**.

Recurrence Relation Derivation: T(N) = T(N/2) + O(1). At each step, the problem size halves, and constant work is done for comparison.

Formal Worst-Case Induction Deduction: Let $N$ represent the initial capacity boundaries. After k sequential split modifications, the remaining subset size is exactly $N / 2^k$. The loop stops when $N / 2^k = 1$, solving to $k = \log_2 N$.

  • Best-Case Complexity: $O(1)$ — Target found at first mid index.
  • Average / Worst-Case Complexity: $O(\log N)$ — Target found at leaf or not found.

Space Complexity Evaluation

  • Iterative Strategy (Implemented Here): $O(1)$ Constant Space

  • Recursive Strategy: $O(\log N)$ Stack Memory Overhead
