Bubble Sort: Classical vs Optimized

Understanding the evolution of Bubble Sort through optimization techniques

Time Complexity Analysis | Space Efficiency | Performance Comparison

Classical Bubble Sort

Traditional Approach
Time Complexity: O(N²) in all cases
Best Case: O(N²) - Still checks all pairs
Worst Case: O(N²) - Reverse sorted
Average Case: O(N²)
Space Complexity: O(1) - In-place
function classicalBubbleSort(arr) {
     let n = arr.length;
     for (let i = 0; i < n - 1; i++) {
        for (let j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                [arr[j], arr[j+1]] = [arr[j+1], arr[j]];
            }
        }
    }
     return arr;
}
  • Always runs N² comparisons - Even for sorted arrays
  • Predictable but inefficient - No early termination
  • Simple implementation - Easy to understand
  • Educational value - Great for teaching sorting basics
  • Stable sort - Preserves relative order of equal elements

    • Optimized Bubble Sort

    Enhanced Version
    Time Complexity: O(N²) Worst / Avg
    Best Case: O(N) - Already sorted array
    Worst Case: O(N²) - Reverse sorted
    Average Case: O(N²)
    Space Complexity: O(1) - In-place
    function optimizedBubbleSort(arr) {
         let n = arr.length;
         for (let i = 0; i < n - 1; i++) {
            let swapped = false;
             for (let j = 0; j < n - i - 1; j++) {
                if (arr[j] > arr[j + 1]) {
                    [arr[j], arr[j+1]] = [arr[j+1], arr[j]];
                    swapped = true;
                }
            }
             if (!swapped) break;
        }
         return arr;
    }
  • Early termination - Stops when no swaps occur
  • O(N) best case - Efficient for nearly sorted data
  • Adaptive algorithm - Performance adapts to input
  • Less redundant passes - Saves unnecessary iterations
  • Same simplicity - Minor code addition, big improvement

    • Key Differences at a Glance

    Feature Classical Bubble Sort Optimized Bubble Sort
    Early Termination ❌ No - Completes all passes ✅ Yes - Stops when sorted
    Best Case Complexity O(N²) - Still checks all pairs O(N) - Single pass detection
    Number of Passes Always N-1 passes Variable (1 to N-1 passes)
    Comparisons in Best Case N-1 comparisons N-1 comparisons
    Comparisons in Worst Case N(N-1)/2 ≈ N²/2 N(N-1)/2 ≈ N²/2
    Swaps in Best Case 0 swaps (still loops) 0 swaps + early exit
    Adaptive Behavior ❌ Non-adaptive ✅ Adaptive - responds to input
    Extra Variable Overhead Minimal (loop counters only) +1 boolean flag (negligible)
    Performance on Sorted Data Poor - still O(N²) Excellent - O(N)
    Performance on Random Data O(N²) - Full passes O(N²) - Similar to classical
